# Contributing to CraftLayer Studio repositories

Thank you for taking the time to help. This guide applies to every public
repository in the craftLayer-studio organization unless a repository has its
own `CONTRIBUTING.md`.

## Before you start

- Read the [Code of Conduct](CODE_OF_CONDUCT.md). By taking part you agree to follow it.
- Security problems must not be reported in public issues. Follow [SECURITY.md](SECURITY.md).
- For project enquiries (hiring the studio), use the
  [contact page](https://craftlayer-studio.github.io/contact/) instead of an issue.

## Reporting a bug

1. Search existing issues first; add details to a matching one instead of opening a duplicate.
2. Open a new issue with the **Bug report** form.
3. Include the page URL, what you expected, what happened, your browser and device,
   and the smallest set of steps that reproduces the problem.

## Suggesting a change

Open an issue with the **Feature request** form and describe the problem you want
solved before the solution. Small fixes (typos, broken links) can go straight to a
pull request.

## Pull requests

1. Fork the repository and create a branch from `main`.
2. Keep each pull request focused on one change.
3. Follow the repository's README for setup. The websites use pnpm, Next.js static
   export and the Astryx design system; run the checks the README lists
   (typically `pnpm lint`, `pnpm typecheck`, `pnpm test` and `pnpm build`).
4. Fill in the pull request template, including how you tested the change.
5. Content rules: do not add clients, testimonials, metrics, awards or other claims
   without a public evidence link. Concept demos must stay labelled as fictional.

A maintainer will review your pull request. We may ask for changes or decline a
change that does not fit the project; we will explain why.
